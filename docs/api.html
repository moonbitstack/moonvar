fixed

moonbitstack/moonvar/fixed

Byte order for the widths a machine has: u8 to u64, the 24-bit length TLS and HTTP/2 use, floats, and a width carried in a variable.

Types

enumOrder

Which end of a number goes first (RFC 1700 calls the big end "network byte order").

pub(all) enum Order {
  • Big
  • Little

Values

letorder

Big-endian, because every protocol in reach of this package writes that way: IP and everything over it, TLS, QUIC, HTTP/2 and HTTP/3. The exceptions are local formats — MySQL's wire protocol, most file headers — and they say so.

pub let order : Order

fnread_uint

The value in size octets at at, for a width the caller only knows at run time. The named widths above are what most callers want and read better where they apply. This is for a protocol that spells its own: MySQL's int<n> and the three-octet lengths of a Kafka or DNS field are the same arithmetic with size carried in a variable, and writing the loop out again per protocol is how the widths drift. None when size is outside one to eight octets, or when the view is shorter than at plus size.

quic

moonbitstack/moonvar/quic

RFC 9000 §16. Two bits name the width, sixty-two carry the value.

Values

letmax

The largest value the encoding can carry: sixty-two bits (RFC 9000 §16).

pub let max : UInt64

Encoding

fnencode

Encode v as a QUIC variable-length integer (RFC 9000 §16) in the shortest form that holds it: the two most-significant bits of the first byte select the length (00 → 1 byte / 6-bit value, 01 → 2 / 14-bit, 10 → 4 / 30-bit, 11 → 8 / 62-bit) and the remaining bits carry the value big-endian. v must be below 2^62 (QUIC's varint ceiling).

pub fn encode(UInt64) -> Bytes

Decoding

fndecode

Decode a QUIC variable-length integer at the start of b, returning its value and the number of bytes it occupied, or None when b is shorter than the length its first byte's prefix declares.

pub fn decode(BytesView) -> (UInt64, Int32)?

Measuring

fnsize

How many octets v takes, without writing it. A writer that has to put a length before a payload needs this: the length field's own size is part of what it describes, and measuring twice is cheaper than writing twice.

pub fn size(UInt64) -> Int32

prefix

moonbitstack/moonvar/prefix

RFC 7541 §5.1. A value in the low N bits of the first octet, continuing when it does not fit — HPACK, and QPACK unchanged.

Values

letlimit

The largest value this reads, which is what a positive Int holds. §5.1 leaves the ceiling to the implementation and asks for a decoding error past it, so a peer cannot make a reader loop over continuation octets for as long as it likes.

pub let limit : Int64

Encoding

fnencode

v in the low prefix bits of the first octet, continuing into further octets when it does not fit (RFC 7541 §5.1). flags are the bits above the prefix, which every representation using this encoding puts something in: HPACK's six field representations and QPACK's five each begin with a pattern there. They are OR'd into the first octet and are the caller's to get right. The three worked examples of Appendix C: ten in a five-bit prefix is one octet, 1337 in five bits is three, and forty-two at an octet boundary is one.

pub fn encode(Int32, prefix~ : Int32, flags? : Int32) -> Bytes

Decoding

fndecode

The value at at and how many octets it took, with the flag bits above the prefix masked off and ignored (RFC 7541 §5.1).

pub fn decode(BytesView, at? : Int32, prefix~ : Int32) -> (Int32, Int32) raise Refused

fnflagged

Whether the octet at at has its high bit set — the H bit of a string literal in both header compressions, which says the octets after the length are Huffman-coded (RFC 7541 §5.2, RFC 9204 §4.1.2).

pub fn flagged(BytesView, at? : Int32, bit? : Int32) -> Bool

Errors

errorRefused

Why a prefix integer was refused. Truncated is a value that continues past the end of what it was given; Exceeded is one that needs more than a positive Int can hold. RFC 7541 §5.1 makes a value larger than the implementation's limit a decoding error, and an encoding of the same value in more octets than necessary is one too — a receiver that read either would disagree with the sender about what came next.

leb128

moonbitstack/moonvar/leb128

Base-128 varints: seven bits an octet, least significant first, plus the zigzag that keeps signed values short.

How many octets sixty-four bits can occupy: nine of seven bits and one of the last. A reader that did not stop here would follow continuation bits for as long as a peer cared to send them.

fnzigzag

A signed value folded onto an unsigned one so that small magnitudes stay short: -1 becomes 1, 1 becomes 2, -2 becomes 3 (protobuf's sint32 and sint64). Without it a negative value would sign-extend to sixty-four bits and take all ten octets, whatever its magnitude.

lenenc

moonbitstack/moonvar/lenenc

MySQL's length-encoded integer: one octet below 251, otherwise a marker and little-endian octets.

Encoding

fnencode

v as a length-encoded integer: one octet under 251, otherwise a marker saying how many little-endian octets follow. The markers are 0xfc for two, 0xfd for three and 0xfe for eight; 251 through 255 are never written as a bare first octet, which is what leaves 0xfb free for NULL and 0xff for an error packet.

pub fn encode(UInt64) -> Bytes
